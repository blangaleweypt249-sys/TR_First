# Electronic_Scram 串口 DMA 透传说明

## 当前行为

`Send` 和 `Receive` 均使用 USART3 连接 LoRa，USART1 作为另一侧串口，原样双向转发字节流：

```text
LoRa TX -> 小板 PB11 / USART3_RX -> DMA 接收环形缓冲 -> USART1_TX / PA9
LoRa RX <- 小板 PB10 / USART3_TX <- DMA 发送队列     <- USART1_RX / PA10
```

两块小板均为 115200、8N1、无硬件流控。对接设备必须交叉连接 TX/RX 并共地。
本次不修改或联调 `Master` 工程，USART1 保留为对外通信口，可先连接串口工具验证。

- 已删除 PA0～PA3 开关轮询、用户层输入重新配置、`sw_bits` 和旧的 3 字节状态帧生成逻辑。
- 不再调用 `RemoteLink_PollSwitches()` 或 `RemoteLink_ForwardRawFrame()`。
- 不限定报文长度，不解析帧头、不修改载荷、不自动生成心跳；例如收到 8 字节就转发相同的 8 字节。
- 两端 `User/remote_link.c` 均不读取或写入 GPIO。LoRa 模式脚电平由 `MX_GPIO_Init()` 的 CubeMX 配置负责。
- `Receive/User/my_main.c` 保留 PA15、PB3～PB9 在初始化阶段拉高，通信期间不改变它们。
- 当前固件是串口桥，不执行按键急停输出或失联急停动作；不要把它当作完整的急停控制实现。

## DMA 配置

两块板的 `F103C8T6.ioc`、串口初始化、DMA 绑定及中断入口已同步修改。

| 串口 | 引脚 | 接收 DMA | 发送 DMA |
| --- | --- | --- | --- |
| USART1 | TX=PA9、RX=PA10 | DMA1 Channel5，CIRCULAR | DMA1 Channel4，NORMAL |
| USART3 | TX=PB10、RX=PB11 | DMA1 Channel3，CIRCULAR | DMA1 Channel2，NORMAL |

每路串口分别使用：

- 512 字节 DMA 循环接收缓冲。
- 1024 字节软件发送环形队列；普通 DMA 按连续区段发送，完成回调继续发送后续区段。
- `HAL_UARTEx_ReceiveToIdle_DMA()`，保留半满、全满和 IDLE 事件；主循环也读取 DMA 当前位置，及时处理不足半缓冲的数据。
- UART 与 DMA 中断优先级均为 5，避免同一路的接收位置维护被同优先级回调嵌套打断。

发送 DMA 故意不设置 CIRCULAR，否则会反复重发旧缓冲区；发送侧的“环形”由软件队列实现。
启动 DMA 的前提是 CubeMX 已完成 GPIO、USART1、USART3 初始化。当前 DMA 时钟及 NVIC 使能位于串口 MSP 的 USER CODE 区；CubeMX 再生成后的 `MX_DMA_Init()` 需在串口初始化之前调用，`.ioc` 中已设置生成顺序。

## 缓冲与异常处理

- 发送忙时保留队列，之后重试；DMA 正在发送的存储区不会被新数据覆盖。
- RX 缓冲被覆盖时丢弃积压数据并计数，不把已经覆盖的内容继续作为完整数据发送。
- UART/DMA 错误只在中断中标记，主循环停止并重新启动该串口的 DMA 接收；故障端口的待收发数据会丢弃，避免沿用损坏状态。
- 调试器可观察 `ports[0]`（USART1）、`ports[1]`（USART3）的 `uart_errors`、`rx_overruns`、`dropped_bytes`。
- 不保证故障或溢出后的报文完整性；上层协议应自行进行帧同步、校验和超时处理。
- 缓冲容量有限且未启用硬件流控；长时间阻塞主循环、禁止中断超过一圈接收时间、或持续输入大于输出能力，都会丢数据。中断阻塞跨越多圈时无法仅凭 DMA 当前位置准确统计丢失量。
- LoRa 模块的串口参数应与小板一致；模块空中参数及对端配置仍需独立确认，本代码不配置无线模块。

## 验证步骤

1. 先断开执行机构，仅进行串口与 GPIO 测试。
2. 用串口工具向 USART3 输入 `A5 5A 12 34 56 78 9A BC`，确认 USART1 原样输出，空闲时不重复发送。
3. 向 USART1 输入任意字节流，确认 USART3 原样输出。
4. 测试短包、超过 512/1024 字节的长流、双向同时收发；检查内容顺序和错误计数。
5. 验证串口错误后能够恢复接收；实测 PA15、PB3～PB9 不随收发数据改变。

两块 Keil 工程已编译通过；主机模拟验证了双向透传、RX/TX 回绕、发送忙重试、RX 溢出、错误恢复和 32 位计数回绕。模拟测试不能替代实际硬件与 LoRa 链路测试。
